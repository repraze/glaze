# Same standard: what the Glaze site copies, and how to share it

The Glaze docs site is built to KernelKit's site standard (GUIDELINES.md §7b/§7c). Everything it takes from the
`@repraze/kernelkit` **package** is shared already: SiteHeader, SiteLayout, SiteSidebar/SiteMain/SiteAside,
Sidebar, Toc + `useTocActive`, Pager, PageHeader, SearchTrigger + `useSearchHotkeys`, SearchDialog/SearchItem,
ThemeProvider/ThemeMenu/`themeScript`, Hero, Section, Carousel, Card/LinkCard, CodeBlock + `useHighlightedCode`,
Empty, Alert and the form controls.

What KernelKit's site implements **locally** had to be copied. This file lists each copy, its source, how far
it diverged, and a proposal for moving it into the kit so KernelKit, TermiColor and Glaze share one
implementation. Paths: `kk/` = `kernelkit/packages/site/`, `tc/` = `termicolor/packages/site/`,
`gl/` = `glaze/packages/site/`.

## 3. Where Glaze deliberately differs from KernelKit's site

- **Notes come before the demos in each docs file.** `extractFunction` takes everything from a demo's
  `export function` to the next `export`, so a trailing non-exported `Notes()` (or constants) lands in the last
  demo's Code tab. That happens on KernelKit's own Introduction page today ("At a glance" shows `Notes`). Fix in
  the kit: stop at the function's closing brace (parse with TypeScript, as `docs-meta` already does).
- **`sections` in `DocDef`**: Glaze's pages have long explanations; their h2s join the ToC.
- **No `lint:design`**: it lints the kit's component sources, which this repo doesn't have. Scene colors are
  hex strings by design (the engine takes CSS hex), which that linter would flag.
- **No shadcn registry** (`registry` script, `public/r`): nothing to distribute as source.
- **The engine is served from source through an alias**, not the `@repraze/source` condition: the condition
  would also switch the npm-installed kit to its sources. The engine's exports still carry the condition, so a
  sibling site that links `@repraze/glaze` gets the TermiColor trick for free.
- **`ci.yml` uses `permissions: {}` at the top level** with `contents: read` on the job, like `pages.yml` and
  `publish.yml`, where KernelKit's ci.yml grants `contents: read` at the top level.
- **The kit's highlighter has no WGSL**: WGSL samples render as plain text with a "wgsl" title. Proposal: add
  `wgsl` to `lib/highlighter.ts`'s language map (shiki ships the grammar).

## 4. Open items

- `gl/src/brand/mark.test.ts` (written with the brand mark) imports `vitest`, which this repo doesn't install,
  so `npm run typecheck` reports it. Either add vitest (as TermiColor does) or port the test to `node:test`
  like the engine's tests.
- The review matrix (`/review/<slug>`) scopes the UI per theme, but scene colors follow the page's theme
  (`useTheme`), not the `ThemeScope` around them: a `useThemePalette()` in the kit that reads the nearest scope
  would fix both.
